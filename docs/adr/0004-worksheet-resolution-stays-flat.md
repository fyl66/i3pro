# 工作表解析不再另加一层 module（前端保持扁平）

2026-10-06 的架构评审把「`viewer.html` 里工作表 → 本场可用的组件与通道这条解析链」
列成了候选（C5，当时标为 Speculative）。动手前量的结果是：**这条链已经是单源的，
再加一层只会是中间人**，所以不做。记下来，免得下一轮评审再提一遍。

## 量出来的事实（2026-10-06，HEAD `53da4de`）

| 环节 | 现在长什么样 | 调用点 |
| --- | --- | --- |
| 工作表清单（读文件 + 跳过不认得的组件类型 + 坏文件说明） | `worksheetCatalogue()`，**带缓存** | 9 处 |
| pick 规则落地 | `resolvePickValue()` / `applyPicks()`，只被 `componentsOfWorksheet()` 用 | 2 处 |
| 三态（present / empty / missing） | `channelState()` —— ticket #34 就是为"只判一次"做的 | 3 处 |
| 别名落到哪条通道 | **判定在 Python**（`aliases.landing`，ticket #46 收成一个 module），前端只查表 | 查表 12 处 |
| "缺了哪几条" | 两个**不同**的概念，各自单源：`PAYLOAD_MISSING`（服务端被点名却没解出来的）与 `workbenchMissing()`（工作表引用却没解出来的） | 各 1 处定义 |

真正重复问同一句话的是 `currentSheet()`（14 处）与 `worksheetCatalogue()`（9 处），
但两者都是**缓存过的 7 元素扫描**：一次调用是微秒级，14 次也只是微秒级。

## 为什么不加那一层

- **删除测试**：把这条链包成一个 `WORKSHEET` 对象，删掉它复杂度不会消失，只是换个名字
  再来一遍——那是中间人，不是深 module。
- **复杂度已经集中**：三态一处（#34）、别名判定一处（#46，还在 Python 侧）、组件类型注册表
  一处（#20）。剩下的是"查表"，查表不需要再包一层。
- **规则 5 / ADR-0002 压着**：`viewer.html` 必须是一个文件、双击即开、无构建。为几百行
  的解析链引入一层内部抽象，换来的是"读的人要多跳一次"，收益为负。

## 什么时候该翻案

如果出现下面任意一条，这条结论就该重来：

1. 一个**新消费者**要自己拼装这条链（例如再加一种"按工作表算的报表"），而不是查表；
2. `currentSheet()` / `worksheetCatalogue()` 的调用点涨到几十处，或者它们开始做**非**
   查表的事（重新读文件、重新算通道状态）；
3. 前端被允许拆成多个文件（那要先翻 ADR-0002）。
