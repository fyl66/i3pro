# DBC 布局进仓库（车队日志仍然不进）

2026-10-07 用户确认：`i2pro_data/dbc/` 里那 34 份 DBC **进仓库**。此前规则 8 与
`.gitignore` 把它们和 `.ld` 一样按"本地数据"挡在外面。理由与边界写在这里，免得下一个人
以为 `.gitignore` 里那条例外是手滑。

## 为什么翻

- **没有它就解不出 CAN 报文**：DBC 是 CAN 场次的解码依据。目录空着时
  `read_can_session` 直接报"找不到任何 DBC"——只剩一堆读不懂的字节。换台机器、或者
  队友只 clone 仓库没有车队数据目录时，工具看起来就是坏的。
- **它小、而且是文本**：34 份合计约 100 KB（最大的那份 dashboard 31 KB），能 diff、
  能评审；旁边的日志是几百 MB 的二进制。
- **它不含别人的隐私**：DBC 描述的是**我们自己车**的 CAN 布局（报文 / 信号 / 位置 /
  缩放 / 单位），没有账号、密钥或供应商机密文档。里面有 AMK / E27 这类**零件型号**，
  与仓库里已经公开的照片、BOM 同类。

## 边界（翻的是"这一样"，不是"i2pro_data 都可以进"）

- **只放行 `i2pro_data/dbc/**`**。同一目录里的日志（`.ld`/`.ldx`）、导出
  （`.csv`/`.xlsx`）、侧车（`*.laps.json` 等）**照旧不进**；`can_data/` 里那 300 MB
  原始 CAN 帧日志也不进。
- `.gitignore` 的写法是 `/i2pro_data/*` + `!/i2pro_data/dbc/**`。**`!` 那条必须写在
  `*.dbc` 后面**：git 按"最后一条匹配的规则赢"，写前面等于没写（第一版就是这么踩的，
  `git check-ignore -v` 一眼看出来）。
- DBC 进仓库之后**不再**是"随手改的本地文件"：改一份会让 CAN 场次的解码结果变
  （通道数 / 单位 / 覆盖率），所以改完要重跑四道回归，并把 ACCEPTANCE 里相关数字重测
  （A50–A55、A62–A66 都写着它们，规则 2）。

## 考虑过的其它做法

- **DBC 不进，工具里带一份"最小样例"**：样例解不了真车数据，等于没解决。
- **DBC 进，但放进单独的公开仓库**：多一个要同步的地方，而它们只有 100 KB。
- **DBC 进，但打成一个 zip**：不能 diff，评审时看不出改了什么。
