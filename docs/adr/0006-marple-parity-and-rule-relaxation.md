# 逆向对齐（Marple）的边界，与三条硬规则的放宽

2026-10-17，用户批准"用 REA 逆向 Marple Insight、择优搬进 i3pro"这条路线，并明确
"可以忽略一些原先的规则"。这一条把**哪些规则放宽、放宽到什么程度、什么没有放宽**写死，
免得下一个人以为 AGENTS.md 里那几条是被谁手滑删掉的。对照表在
[`docs/marple-parity.md`](../marple-parity.md)，采集规程在
[`docs/marple-runtime-capture.md`](../marple-runtime-capture.md)。

## 决定一：只对齐行为，不搬运实现

- 复刻的是**能力、接口形状与交互**；不复制 Marple 的代码与静态资源，不做像素级版式抄版。
- **i3pro 不调用 Marple 的后端 API**，不引入它的账号、连接器、时间序列库。
- 证据全部来自公开交付给浏览器的静态包（任何能打开该页面的人都收得到同一份字节），
  只做只读采集；邀请链接里的一次性邀请码**不写进仓库**（仓库公开）。

## 决定二：放宽三条

1. **`viewer.html` 不再是"必须单文件、无构建、无 CDN"**（修订 [ADR-0002](0002-single-file-frontend-no-build.md)）。
   允许 vendored 的单文件依赖，或在启动脚本里承担构建；**但"双击 `启动.bat` 就能用"不许破**，
   且每引入一个依赖要单独写 ADR 说明代价与退出方式。
2. **运行期依赖白名单不再是封闭集合**（修订 AGENTS.md 规则 4）。新增依赖照旧要写 ADR；
   规则从"只允许这四种"变成"默认这几种，例外要有 ADR"。
   **注意第二道闸**：`tests/test_i3pro.py` 里那份硬编码的 `RUNTIME_PACKAGES` 白名单不是
   从 AGENTS.md 读的，加依赖的那张票要**同时**改它，否则测试会红——这是有意的
   （防漂移），别把它当 bug 绕过。
3. **五件套对"纯 UI 组件"按比例执行**（修订 AGENTS.md 规则 1）。画法、布局、配色、
   交互外观这类改动不必凑齐五件，但**必须留下一条可跑的验收命令或截图判据**。
   算法、解析、统计、导出这类"错了看不出来"的改动，五件套照旧一件不能少。

## 决定三：三条没有放宽

1. **文档里每个数字必须实测**——这条是仓库可信度的地基，放宽它等于允许"设计目标"伪装成"已实现"。
2. **`tools/verify_ld_vs_csv.py` 必须始终 PASS**——解析正确性只认这一个裁判。
3. **面向队友的文案用中文，报错要说下一步做什么**——这是产品可读性，不是负担。

另外，`docs/PLAN.md` 里"不做云端多人协作 / 账号体系"这类**产品定位**的取舍**没有被放宽**：
Marple 的 workbook 库、dashboard 服务端、连接器、AI 出图属于这一类，照旧不做
（详见对照表的"不做"一节）。

## Considered Options

- **原样保留单文件约束**：最保守，但姿态图 / PFD 指望不上 3D，热力图与表格也要重复造轮子；
  代价是这一轮能拿的差异点基本作废。
- **放开到"随便上 npm"**：省事，但离线可用与"发一个文件给队友"两条同时失守，
  这正是 ADR-0002 当初否决 React + uPlot 的理由，没有变。
- **本 ADR 的路线**：按能力分级放宽——**只给具体票开口子，开口子必须留 ADR 与退出方式**。
