# `.csv.gz`：纯文本场次的**只读**压缩容器

合并出来的宽表场次一份就 100–300 MB（2026-10-25 那天 15 份合计 2.72 GB），共享目录
因此涨到 7.3 GB。这份 ADR 记的是：**给纯文本场次加一个 gzip 容器，只读**，以及为什么
不是 xlsx、不是 Parquet、不是文件系统压缩。

## 实测（2026-10-25，本机）

| 方案 | 15 份合并产物 | 读一份 290 MB 的额外代价 | Excel 双击 |
| --- | --- | --- | --- |
| 裸 CSV（原状） | 2724.1 MB | — | 能 |
| **`.csv.gz`** | **339.2 MB（12%）** | 解压 0.6 s（453 MB/s，比解析本身快） | 不能（要先解压） |
| xlsx | ~2750 MB（更大 1–8%） | 读回 57.5 s（同内容 CSV 2.6 s） | 能 |
| NTFS 压缩 | ~1430 MB（1.9:1） | 无 | 能 |
| Parquet | ~294 MB | 快 | 不能 |

xlsx 那条是这个决定里最容易走错的一步：它是 zip + XML，**格子标签本身就比数据贵**，
所以压完更大、读起来慢 20 倍（仓库里 `export.py` 早就记过 CSV 3.36 B/格、xlsx
3.80 B/格，这次在真文件上复现）。Parquet 更小，但它要新写一条"场次读取器"，而且现有
`store.build_table` 落的是 `float32`（7 位有效数字），经纬度会掉到约 1 米分辨率——
"更小"不该用 GPS 轨迹变糙来换。

## 决策

1. **只有纯文本容器能压**：`.csv` / `.txt` / `.tsv`。`.ld`（二进制）与 `.xlsx`
   （本来就是压缩容器）明确拒绝，报错里直接写"解压回原样"，而不是"压了但没人读得动"。
2. **身份 = 主名**：`X.csv.gz` 的场次名是 `X`——压缩后缀与格式后缀都不进身份。
   侧车跟着身份走（`X.laps.json`），所以 `X.csv` 与 `X.csv.gz` 共用同一份用户改动，
   两个容器同名并存时侧边栏显示 `X` 与 `X (csv.gz)`。判断只在
   `i3pro.containers` 里做一次（`Path("X.csv.gz").stem` 是 `X.csv`，那正是老毛病）。
3. **帧表不参与**：`.csv.gz` 一律当通道表读，`canlog.looks_like_frames` 只认裸 `.csv`。
   场次库启动时会对每份 `.csv` 做内容嗅探，压缩帧表会让那趟扫描变成逐份解压；
   而且帧表是记录仪工具链与 MoTeC 的输入，压它收益小、代价大。
4. **i3pro 只读，不写**：命令行没有这个子命令、导出面板没有这一档。唯一的"写"是开发
   工具 `tools/make_csv_gz.py`，它**刻意**用裸 zlib 自己写 gzip 头（`mtime=0`、不写
   原文件名）：默认的 gzip 头带时间戳与原文件名，同一份 CSV 两天压出来字节不同，
"共享里那份 `.gz` 和本地这份是不是同一份"就只能靠大小猜。省空间要配上能机械复核。
5. 导入收 `.csv.gz`（`.xlsx.gz` / `.ld.gz` 当场拒），索引页的 `accept` 里也写上它。

## Considered Options

* **转成 xlsx**：否决。更大、更慢（上面的实测），而且它已经是压缩容器，再压是白费。
* **转成 Parquet 当场次格式**：否决。`float32` 的精度代价落在坐标上最难看；真要做得先
  把坐标列改成 `float64`，那是另一份 ADR。
* **只靠 NTFS 压缩**：否决作为主答案（1.9:1 对 8:1），但它零改动、Excel 照旧，所以
  留在备选里——想要"省一半又不改任何东西"时，那条路一直可用。
* **保持裸 CSV**：否决。合并产物会一直长大，而它们每次都能从 `.ld` + 帧表重算，
  正是最适合压着放的那一类。

## 后果

* 共享目录按用户的选择**同时**留 `X.csv` 与 `X.csv.gz`（队友双击 Excel 用前者），
  所以共享是变大 339 MB 的那一边，省下来的 2.38 GB 落在本机 `i2pro_data`。
* `.gitignore` 必须补一条 `*.csv.gz`：`*.csv` **挡不住**它（那条规则只看最后一段），
  漏了就会让 `git add -A` 把几百 MB 车队数据带进仓库。
* 依赖没有变化：`gzip` / `zlib` 是标准库，不走 ADR-0006 的依赖例外。

## 退出方式

要加"i3pro 自己导出 `.csv.gz`"或"Parquet 当场次"时，先写新的 ADR；那两件事都只需在
`containers.COMPRESSIBLE` / 读取器分派处各加一条，`sidecar` / 场次库名字这些已经按
主名收敛的规则不用再动。
