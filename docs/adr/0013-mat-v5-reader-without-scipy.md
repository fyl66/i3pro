# 逆变器日志的 `.mat` 用手写 MAT v5 读取器（不引入 scipy）

德雷斯顿（Ephorus）电机控制器导出的日志是 **MATLAB v5**（由 TinyMAT 写），不是 v7.3
HDF5。规则 4 原先只允许 `numpy` / `pandas` / `pyarrow`，`scipy.io.loadmat` 会是一个新的
运行期依赖，所以按 ADR-0006 先在这里把边界钉死。

## 决定

在 `src/i3pro/matlog.py` 里**手写** MAT v5 的读侧：numpy 解数值块，标准库 `zlib` 解
`miCOMPRESSED`。读出来的表交给 `csvlog.session_from_frame` 装配成场次——与 CSV / Excel
是**同一条**路径，所以画图、数学通道、导出、侧车全都不用另写一份。

## 为什么现有工具做不到

- **`scipy.io.loadmat` 按规格读，这批文件不是按规格写的**：实测根目录那几份 TinyMAT
  文件**不补齐** MI 元素的 8 字节对齐，按规格走会在第 3 个变量处错位（tag 读成
  `12316` 这种垃圾值）。也就是说，就算肯加依赖，也仍然要在外面兜一层"规格外"的容错
  ——那层容错本来就要自己写，依赖省不下这件事。
- **先转成 CSV 再导入**：能救急，但每来一份新日志都要再转一次，而且多一份比原文件大
  几倍的中间产物；车队每次练完都来一批，手工步骤迟早被跳过。
- **`h5py` / v7.3**：这批文件不是 v7.3，用不上；MATLAB v5 的读侧只有几百行，比多背一个
  HDF5 依赖便宜。

## 代价与边界

- 只认**数值矩阵**（`double` / `single` / 各种整数）。`struct` / `cell` / `char` /
  复合类型遇到时明确报错并说下一步（用 MATLAB 另存成矩阵表），**不静默跳过**。
- 同名的重复变量（实测每份 5 条：`Reserved_1..3`、`Use_*_Ethernet`）加 `_2` 后缀保留
  ——不替用户决定哪一条是"对的"。
- 与 `.ld` 一样**只读**：任何单位覆盖、降采样结果都只进侧车，不写回 `.mat`。

## 怎么退出

所有读法收在 `matlog.py` 一个文件里：文件头校验、tag 读取（补齐/不补齐两种）、
`miMATRIX` 拆解、`zlib` 解压、同名去重、按后缀猜单位、降采样。上层看到的一直是
"一张列 = 通道的表 + 一个导入报告"。要换成 `scipy` 或改成读 v7.3，只动这一个文件，
`session_from_frame` 与它下游全都不变。

解析阶段只保存各数值块的偏移，不另造一份数组；`read_variables()` 随后把全部数值
通道复制成 `float64` 并装配场次。也就是说，"不复制"只描述 tag 扫描这一小段，不是
整场冷启动的内存承诺；将来若要只读表头和 `t`，必须另做一条有实测的快速摘要路径。
