# 部署自查清单（把 i3pro 放到公网上）

用户问的是：能不能把它部署到 `https://aurora-racing.com/`，让大家联网就能用。
**这一页只帮你把"能不能"查清楚**，不含任何部署实现——查清楚之后单独开一票做。
(`docs/PLAN.md` 里"云端多人协作 / 账号体系"目前写着**不做**；真要翻案，改 PLAN
之外还要按 `AGENTS.md` 的规矩补一份 ADR，说清谁能看、能不能传、数据怎么清。)

## 0. 已经查明的事实（2026-10-12 实测）

| 项 | 实测 |
| --- | --- |
| 官网形态 | `Server: nginx`、HTML 里 `/assets/index-LozsxO1Z.js` + `<div id="root">`：Vite 构建的静态站；图片与字体走 `cdn.aurora-racing.com` |
| 首页 | 只有 1977 字节的壳，没有 WordPress 之类的动态程序 |
| i3pro 的 URL 形状 | 全是**根绝对路径**（`/api/...`、`/session/...`）→ 只能挂在**子域名**的根路径（例如 `i3pro.aurora-racing.com`）；塞进 `aurora-racing.com/i3pro/` 子路径要改写全部链接 |
| 鉴权 | **没有**。`src/i3pro/server.py` / `api.py` 里没有口令、没有登录、没有会话 |
| 上传 | `/api/upload`（PUT）与 `/api/import` 已经能用，上限 2 GB（`api.py:56`）——**现在是匿名可写** |
| 可见性 | 首页把**所有场次**列出来（`indexpage.py:265`），点进去就能看每一场的数据 |
| TLS | i3pro 自己不做 TLS，要 nginx 在前面终止（官网已有 HSTS，证书这条路是通的） |
| 并发 | 单进程 `ThreadingHTTPServer`，没有限流；几十个人同时看没问题 |
| 一个场次的开销 | `.ld` 用 mmap + LRU（`serve --cache`，默认 3）；实测 36 MB 的场次出快照约 1 s、118 MB 约 2 s |

## 1. 先查那台机器能不能跑 Python 服务（只有你能查）

在服务器上（SSH 或主机商网页终端）跑：

```bash
python3 -V                 # 3.10+ 就行
uname -a                   # 确认是 Linux
nginx -v                   # 确认反代是 nginx（官网响应头已经证实）
systemctl --version        # 能管服务 = 有 root/sudo
```

三种情况：

* **能 SSH / 有 root（或 sudo）** → 走"独立子域 + nginx 反代 + 口令"那条路。
* **只有 FTP 或网页文件管理器，改不了 nginx、装不了东西**（静态托管 / 对象存储）
  → **Python 服务放不上去**。两条替代：
  1. **离线快照**：`python -m i3pro snapshot` 生成一堆自包含 HTML，扔上去当只读页面
     （不能上传、不能改，适合"给队友看圈速"）；
  2. 另找一台小 VPS（1 核 2 GB 就够几十人看）。
* **不确定** → 试这三件事，三样都做不到就是静态托管：能不能装一个包、
  能不能改 nginx 配置、`systemctl status nginx` 能不能用。

## 2. 真要上线，得先定三件事（现在都没定）

| 问题 | 为什么必须先定 |
| --- | --- |
| **谁能进来** | 工具现在**零鉴权**：挂到公网之后，任何人扫到都能看全套数据，还能往数据目录写文件 |
| **数据从哪来** | 上传自己的 `.ld`（要配额 + 清理）/ 只放允许公网的几场 / 只放演示数据——`i2pro_data/` 那种全队数据不能整个挂上去 |
| **挂在哪个域名** | 根路径 URL → 建议单开一个 `i3pro.aurora-racing.com`，`location /` 全转给 `127.0.0.1:8731` |

## 3. 上线要补的缺口（改代码之前先认下来）

* **鉴权**：至少一道口令（HTTP Basic 或一次性 token）。这一条不做，第 2 节第一行就没法落地。
* **数据边界**：`serve --data` 只指向"允许公开"的目录；不能把车队全量数据目录挂上去。
* **上传**：留不留要想清楚；留就要限大小、限频率、限落盘目录，还要有清理。
* **TLS**：交给 nginx（i3pro 不做）。
* **进程守护**：`systemd` 单元（崩了自动拉起）+ **只监听 127.0.0.1**（让 nginx 转发，
  别把 8731 直接暴露给公网）。
* **日志与磁盘水位**：访问日志、上传目录的增长要有人看。

## 4. 判定标准

这一页只负责让你能回答一句话：**"那台机器能不能跑我的 Python 服务？"**

* 能 → 单独开一票做部署（鉴权 + 反代 + 数据边界 + systemd），四条回归照旧要全绿。
* 不能 → 要么走离线快照，要么先弄一台 VPS。
