# 逆向对齐 spec：姿态图、A–B 统计、热力图、绘图分辨率（附 UI/组件逻辑取舍）

**这是什么**：把 [marple-parity.md](marple-parity.md) 里 P1–P4 四条候选 + 一批从 Marple 的
UI 与组件逻辑里挑出来的项，收敛成一份可以直接切票实施的规格。定稿后交给 `/to-tickets`。

**边界**（同对照表）：只复刻行为、接口与交互；不复制代码与静态资源；不做像素级抄版；
不调用它的后端。凡是"靠有个云端后端才成立"的东西（workbook 库、连接器、账号、AI、license 门控）
一律不搬。本轮放宽的规则见 [ADR-0006](adr/0006-marple-parity-and-rule-relaxation.md)——
**但四条能力里没有一条需要新增运行期依赖**，所以实际上一条口子都不用开。

## 0. 一句话

四条能力都落在"**已有数据 + 已有管线**"上：姿态图是新的**画法**（数据早就在 `.ld` 里），
A–B 统计是现有统计换**范围**，热力图是现有二维分箱加**新视图**，绘图分辨率是把散落三处的
抽稀收成**一个旋钮 + 一种更诚实的抽稀方式（分桶包络）**。

## 1. 目标与非目标

**目标**

1. `attitude` 组件：3D 车体姿态视图 + PFD 视图，跟着光标显示，能跟基准光标处的姿态同屏对比。
2. 光标 A–B 区间统计：把现有的可见区间统计扩成"可见区间 / A–B"两种范围。
3. `heatmap` 组件：两通道分箱 + 第三通道（或样本数）着色。
4. 绘图分辨率五档 + 服务端分桶 min/max 包络，并把"这条线是抽稀过的"写在界面上。

**非目标**（本轮明确不做，写下来是为了下一个人不用再问一遍）

- 任意播放 / 动画（PLAN 里 Gauges 动画已剔除，姿态图同样不做播放，只跟光标）。
- 欧拉角顺序可选、自定义 3D 模型上传与管理、three.js 一类的实时 3D 引擎。
- σ / 斜率 / 积分等超出 Marple 的统计量（Marple 只有 min/mean/max；我们的可见区间统计
  也只有 min/max/avg。要用再说，别顺手加）。
- license 门控、按"包"分组的可用性过滤（本地工具没有这个概念）。
- Marple 那套 workbook / dashboard / report template / sandbox 四件套（与 PLAN 的
  "不做云端协作"冲突）。

## 2. 共同约定

- **术语**照 [CONTEXT.md](../CONTEXT.md)：姿态图 / PFD / 光标区间统计 / 绘图分辨率 四条已经写进去了；
  组件、工作表、挑通道、侧车这些不新造词。
- **组件类型只有一处注册**：`src/i3pro/web/viewer.html` 的 `COMPONENT_TYPES`（#17 的教训）。
  现有 10 类：`graph` `scatter` `histogram` `spectrum` `track` `gauge` `delta` `status` `report` `chreport`；
  本轮**只加 2 类**：`attitude`、`heatmap`。
- **配置进工作表**：新增的 `config` 键写在组件的 `encode/decode` 里，跟着 `worksheets/*.json` 走；
  默认值要能"不写也能用"（换场次不炸）。
- **一条出口**：凡是"这个数字是多少"的计算，算法写成不依赖框架的纯函数放 `src/i3pro/`，
  快照 / 服务 / CLI 三个入口共用（仓库既有约定）。
- **四道回归照跑**：`python -m unittest discover -s tests`、
  `python tools\verify_ld_vs_csv.py`（**不可谈判**）、两份金标准 `node tools\smoke_viewer.js`、
  `python tools\verify_clicks.py`。

## 3. T1 · 姿态图 + PFD（组件 `attitude`）

### 3.1 为什么是"两条通道 + 一个组件"

数据实测已在场：两条金标准都带 `Aceinna Roll` / `Aceinna Pitch` / `AngleLocalYaw`
（deg、100 Hz、2 位小数，各 46,400 / 194,300 点），另有 `Roll (2)` / `Pitch (2)` 与 `Longitude MTI` 一类 MTi 通道。
所以这一票只做**画法**，不碰解析。

### 3.2 接口

```
组件类型: attitude
config: {
  view: "model" | "pfd",        // 默认 "model"
  roll: <通道名>, pitch: <通道名>, yaw: <通道名>,
  unit: "deg" | "rad",          // 默认 "deg"
  gains: [gr, gp, gy],          // 每通道倍数，默认 [1,1,1]
  ghost: true,                  // 基准光标处叠 30% 透明模型，默认 true
  grid: true                    // 地面网格，默认 true
}
```

- 挑通道默认优先级（进 `channelpick.py`，与现有 `DEFAULT_CHANNEL_PRIORITY` 同一处）：
  roll → `Aceinna Roll` / `Roll (2)` / 名字含 `Roll`；
  pitch → `Aceinna Pitch` / `Pitch (2)` / 名字含 `Pitch`；
  yaw → `AngleLocalYaw` / 名字含 `Yaw` / 名字含 `Heading`。
  找不到就留空——**不猜**，交给 3.5 的提示。
- 纯函数（新增 `src/i3pro/attitude.py`）：
  `normalize_angle(value, unit, gain)`（角度归一化 + 单位换算 + 倍数，返回弧度）、
  `rotation_matrix(roll, pitch, yaw)`（固定 **ZYX / 3-2-1**：`Rz(yaw)·Ry(pitch)·Rx(roll)`）、
  `project(vertices, matrix, camera)`（正交投影，输入输出都是纯 Python/NumPy）、
  `pfd_scales()`（俯仰 −90…90、滚转 −180…180 的刻度位置，供 PFD 画）。

### 3.3 渲染（纯 Canvas，不引依赖）

- **model 视图**：线框车体（简化长方体 + 前向标记）按 `rotation_matrix` 旋转后正交投影；
  地面网格做视觉参照；鼠标拖拽绕视角转（相机 yaw/pitch 两个标量），`E` 键或组件栏按钮复位。
- **pfd 视图**：天地线随 roll 旋转、随 pitch 平移；俯仰刻度每 10°；滚转弧每 10° 刻度 + 指针；
  顶部航向带每 10° 一格、当前航向居中。
- **跟光标**：主光标处画实心模型；`ghost` 开着且基准光标 A 在图上时，A 处叠一层 30% 透明模型
  （这条**照搬 Marple**，它就是这个交互）。
- **只在状态变化时重绘**（光标移动 / 缩放 / 通道变化 / 配置变化），不做动画循环。

### 3.4 边界与失败

| 情况 | 行为 |
| --- | --- |
| 三条通道缺任一条 | 组件里写一句话：**"给这个组件选 roll / pitch / yaw 三条通道"**，并在组件标题写 `缺 N 条`（复用既有"本场次没有"那套文案） |
| 某帧是 NaN | 该帧不画（不补零、不外推） |
| unit=rad | 纯函数里换算成弧度后统一处理 |
| 角度超出 ±180 | 归一化到 [−180, 180) 后显示；不做多圈累计（**已知边界**，写进验收条目） |
| 快照模式 | 与其它组件一致：数据内嵌，姿态跟着快照里的光标走 |

### 3.5 不做（与 Marple 的差别）

| Marple 有 | 我们不做 | 理由 |
| --- | --- | --- |
| `eulerOrder` 六选一 | 固定 3-2-1 | 六选一是配置坟墓，没人会改。**更正（2026-10-17，评审发现）**：原文写"固定 ZXY，与 Marple 默认一致"，但它的默认值我们**没有实证**（那个 chunk 不在仓库里，只有 minify 过的映射表），所以改成只声明**我们自己**用 3-2-1，不声称与它一致 |
| 自定义 3D 模型（`customModels`，带 URL 与标定） | 不做 | 需要模型托管与格式支持，收益低；线框车体够表达姿态 |
| three.js + 相机控制 | 不做 | 为一张小图引入 1 MB+ 运行时依赖不值；纯 Canvas 正交投影约 100 行 |

### 3.6 验收（A88）

- 单测：`normalize_angle`（deg/rad、倍数、±180 归一化）、`rotation_matrix`（与手算的 90° 特例对照）、
  `project`（已知顶点的手算坐标）、`pfd_scales` 的点数与单调性。
- 无头断言：`attitude` 组件能被注册与添加；三条通道缺失时出现上面那句提示；`ghost` 关掉后幽灵元素不在 DOM。
- 真鼠标（Edge）：拖拽改视角后画布像素发生变化、`E` 复位后回到初始视角、移动光标后画布再变。
- 金标准：`20260908-cjh 高避5圈.ld` 与 `20260524-耐久正赛.ld` 上都能画（上面那三条通道实测存在）。

## 4. T2 · 光标 A–B 区间统计（A89）

Marple 实测只有三个数（`/signals/cursor/stats` → `{min, mean, max}`），所以这一票**不是新算法**，
而是给现有的"可见区间 min/max/avg"加一个**范围开关**：

- 组件栏「显示」里，三项统计量（Min / Max / Avg）旁加一个范围选择：**可见区间**（默认，现状）/ **A–B**。
- 选 A–B 而图上没有基准光标时，抬头不显示数字，改用 `viewer.html` 里**已有那句**原文：
  "没有 A–B：按 D 打开基准光标，把鼠标放到 A 的位置按空格；再移到 B 按空格。"
  （复用，别写第二遍。）
- 统计只在**当前可见的样本**上算（与现有口径一致），A–B 两端**左闭右闭**，与导出那套一致。
- σ / 斜率 / 积分**不做**（见非目标）。

验收：单测（A–B 范围内的 min/mean/max 与 `numpy` 对照、A–B 反序时自动交换、空区间返回空而不是 0）；
无头断言（没有基准光标时的文案）；真鼠标（摆好 A/B 后抬头数值随光标变化）。

## 5. T3 · 热力图（组件 `heatmap`，A90）

**先说清楚证据的成色**：Marple 的 Heatmap 在 Aggregate 组里，本轮**没有运行时证据**（没点开它），
所以这一条**按我们自己的需求定义**，只借它的两件事：它跟直方图同属"聚合类"，
以及它用第三通道着色的思路。下面写的是我们的规格，不是"抄它"。

```
组件类型: heatmap
config: {
  x: <通道名>, y: <通道名>,
  z: <通道名或空>,      // 空 = 按样本计数着色
  bins: [nbx, nby],    // 默认 [60, 40]，范围 8–200
  range: "view" | "lap" | "all",   // 默认 "view"（跟缩放走，与直方图一致）
  scheme: "count" | "z-mean"       // 默认 count；z 非空时默认 z-mean
}
```

- 分箱与着色复用 `histogram.py` 的取样与 `palette.py` 的色带；算法仍写成纯函数（`heatmap.py`），
  与 `numpy.histogram2d` 对拍。
- 色标（图例）标出最小/最大与单位；鼠标悬停写"这一箱有多少点 / z 的均值"。
- 与直方图同一条纪律：**数的是原始样本**，不是抽稀后的点（否则分布会假）。

验收：单测（二维分箱与 `numpy.histogram2d` 逐箱相等、`z-mean` 口径、全 NaN 输入不炸）；
无头断言（组件注册、色标存在）；真鼠标（切换 range 后箱数变化、悬停提示出现）；
金标准上单次响应要有一个实测数字写进 A90（**先量再写，别把目标当结果**）。

## 6. T4 · 绘图分辨率五档 + 分桶包络（A91）

### 6.1 五档旋钮（照 Marple 的量）

Marple 实测：档位名 `Min / Low / Medium / High / Max`，取值 **`500 × 2^档位`** →
500 / 1000 / **2000（默认 Medium）** / 4000 / 8000 点；放在工作区级设置里
（不是每张图一个）。我们照这个来：

- 位置：工作表栏「显示」区（与"曲线连接"并列），文案用中文：**最少 / 少 / 中（默认）/ 多 / 最多**，
  括号里写点数，例如"中（2000 点）"。
- 存哪：跟着工作表走（`worksheets/*.json`），与"曲线连接"同一处读写。
- 生效：快照与服务两条路都按这个点数抽稀。

### 6.2 分桶包络（这是"为什么它看起来丝滑"的答案）

Marple 的取数端点返回的是**每桶的下界与上界**（`low_bound` / `up_bound` / `bucket_count`），
不是插值出来的平滑点；是否降采样由 `估计采样率 × 窗口秒数 > 2 × 分辨率` 决定。
我们照这个改 render 路径：

- 服务模式：按可见区间与当前档位分桶，返回每桶 `min`/`max`；前端把每个桶画成一条竖线，
  相邻桶之间连外轮廓。
- 快照模式：预先按同一规则生成包络并存进载荷（不再存"等距抽稀"的折线）。
- 界面诚实：一旦本次绘制用了包络（原始点数超过 2×档位），图标题上写 **"已抽稀（包络）"**，
  与 A79 的"曲线：阶梯保持"同一族标识。
- 与"曲线连接"的关系：**包络管抽稀，连接管点间**，两者独立；包络模式下连接设置只影响
  桶间连线形态。

验收：单测（桶数 ≤ 档位、首末桶覆盖区间两端、每桶 min/max 与 `numpy` 对照、
`估计采样率 × 窗口秒数 > 2 × 分辨率` 这条判据能复现）；无头断言（"已抽稀（包络）"标识出现/消失）；
真鼠标（切档位后请求点数变化、视觉上点数真的变了）；性能：金标准上切档的耗时**量出来**再写进 A91。

## 7. Marple 的 UI 与组件逻辑：取什么、去什么

**取其精华**

| 它的做法 | 为什么值得取 | 我们怎么落地 |
| --- | --- | --- |
| 加图表时**按用途分组**（Explore / Aggregate / Aerospace），每项一个图标 + 名称 | 13 种类型平铺会挑花眼，分组让人按"我要看什么"找 | 现有 `<select id="addType">` 加 `<optgroup>`：曲线 / 聚合 / 姿态 / 状态与报告。**不引图标字体**（它用 Material Symbols，需要联网字体，我们保持零外部资源） |
| 不可用的选项**置灰并写明原因**（`disabled` + `disabledHoverText`，例如"聚合图暂不可用"） | 比"点了没反应"好得多，符合我们"报错要说下一步"的规矩 | 选到本场次没有通道的类型时，在下拉下面写一行：**"这一场没有 XX 通道，先导入数据或用通道别名指一条"** |
| 空状态给下一步（"Drag signals to start plotting"、"Let's get you some data to visualise" + 一个 Add data 按钮） | 空面板是最容易被误解成"坏了"的地方 | 组件没通道时写"**把左边的通道拖进来**"，并复用既有的"本场次没有"灰显机制 |
| 每个图有自己的设置，全局的东西才放全局（分辨率是工作区设置，轴模式是每图设置） | 避免"设置放在哪"的长期混乱 | 新增的分辨率放工作表栏；姿态图的单位/倍数放组件栏。与现有分工一致 |
| 同一张图能**换类型而保留通道**（`REPLACE_PLOT_TYPE`）、能复制图（`COPY_PLOT`） | 试错成本低 | 组件栏加"换成…"（保留通道与位置）与"复制"（错开一格）。内部深拷贝已有（`copyComponents`），只缺入口 |
| `Subsampled` 状态直接写在图上 | 数据不骗人，正合我们的规矩 2 | 见 6.2 的"已抽稀（包络）" |
| 第三通道参与渲染（`z_signal` 给散点/热力图着色） | 一屏看三个量 | 我们已有（散点第三通道着色），热力图沿用 |

**去其糟粕**

| 它的做法 | 为什么不取 |
| --- | --- |
| 按 license 包（BASE / MOTORSPORT / AEROSPACE）过滤功能 | 本地工具没有这个前提；少一个"为什么我这里没有"的坑 |
| workbook / dashboard / report template / sandbox **四套并列的容器** | 概念重叠，学它等于给自己造四个定义；我们只有工作表 |
| 13 种绘图类型（含 Message / Metadata / State / Table / Number / Bar / PFD…） | 类型越多，每加一个都要碰注册表；我们只加 2 类，其他用现有的 `status` / `report` / `chreport` / `gauge` 覆盖 |
| 以"信号(signal)"为世界中心，文件只是 dataset | 我们的中心是**场次**（一个日志 = 一个场次）；术语已经钉死，不改 |
| 图标字体、在线字体、客服/统计 SDK（Gleap、volces 统计、Inter 字体） | 我们有"离网、双击即开"的硬要求；这些都要联网 |
| 部分报错只说"不行"不说下一步（"Text signals are not supported for this plot type"） | 我们的规矩 6 要求说下一步：**"这条通道是文字量，换个数值通道，或换成表格"** |
| 每个图都留实时/播放模式 | PLAN 已明确不做动画播放；姿态图只跟光标 |

## 9. 风险与已知边界

- **姿态图是唯一"从零写画法"的一票**：没有运行时截图可对照（Marple 那边被 license 挡住），
  验收只能靠"行为对不对"，不能靠"像素像不像"。这是有意接受的：我们要的是能力，不是版式。
- **热力图没有对照物**（见第 5 节），实现自由度最大，也最容易被做成"没人用的图"。
  验收因此绑死"与 `numpy.histogram2d` 逐箱相等"，先把数算对再谈好不好看。
- **包络会让"点样式"变得没意义**：抽稀到 2000 桶时每个点是"一桶的上下界"，
  所以包络生效时点样式自动切回线（并在标题里写明），这是已知取舍。
- **姿态图的角度不做多圈累计**：连续横滚（比如连续翻两圈）显示上会跳。
  真实数据里没出现过，先记着。
