# 工作表（worksheet）

这个目录里每个 `.json` 就是工作台上方那一排按钮里的一个工作表。文件名是它的身份
（ASCII、可放进 URL），文件里的 `name` 是按钮上显示的字。加一套新的就往这里放一个
文件，不用改代码；改坏了不会连累别人——读不出来的文件会被跳过并在界面上报出文件名
和"下一步做什么"。

工作台按 `order` 从小到大排按钮，`order` 相同按文件名排。

## 在工作台上直接改（ticket #33）

不用手写 JSON 也能加一套：工作台左边「工作表」那一栏上下两排——上面一排是"切到
哪一套"，下面一排管的是"这一套本身"。

| 按钮 | 做什么 | 落盘的结果 |
| --- | --- | --- |
| 保存 | 把当前这一屏写回**正在用的那份文件**（名字与排序不动） | 改的是同名那份 `.json` |
| 另存为 | 把当前这一屏存成新的一份 | 多一个文件；同名时加后缀（`sheet-2.json` / `name 2`），**不覆盖** |
| 新建 | 起一套只放一张图的新工作表 | 多一个文件，排在最后（`order` 取当前最大值 +1） |
| 重命名 | 改显示名 | 文件名跟着变，旧文件删掉；目标名已被占用时报错，不覆盖 |
| 删除 | 删掉这一套（**要点两次**：第一次变成「确定删除？」） | 文件删掉；删的是正在用的那套时自动切到第一套并说明 |
| 导出 | 存成一份 `.json` 发给队友 | 字节与 `worksheets/<身份>.json` 一致 |
| 导入 | 收下队友发来的一份 `.json` | 多一套；同名加后缀，不动本地那一份 |

两处要留意：

* **文件名由显示名派生**：只保留 ASCII 字母数字，其余当分隔符；一个字母都不剩
  （纯中文名）就叫 `sheet`，第二份是 `sheet-2`……所以"分析"这套的显示名是
  `分析`、文件名是 `analysis.json`（仓库里这七份是历史命名，不受影响）。
* **`pick` 挑出来的通道名不会写回文件**：保存写的是位置 / 尺寸 / 你自己设的配置，
  文件里那条 `pick` 原样留着。写死通道名的话，换一个场次这张图就空了。

快照（离线 HTML）只有"看与切"：那一排按钮点了会提示改用 serve 模式，因为离线文件
改了也带不走。

## 一份工作表长什么样

```json
{
  "schema": 1,
  "name": "分析",
  "order": 10,
  "hints": ["Vx KF", "Brake Signal"],
  "components": [
    {"type": "graph", "x": 0, "y": 0, "w": 12, "h": 9,
     "pick": {"channels": {"limit": 12}}},
    {"type": "gauge", "x": 0, "y": 9, "w": 4, "h": 13,
     "config": {"subtype": "wheel"}}
  ]
}
```

| 键 | 必填 | 意思 |
| --- | --- | --- |
| `schema` | 是 | 现在只认 `1`。以后改格式时靠它认新旧 |
| `name` | 是 | 按钮上的名字。不能和别的工作表重名 |
| `order` | 否 | 按钮顺序，小的在前；缺省 50 |
| `hints` | 否 | 挑通道用的提示词，见下面「挑通道」 |
| `components` | 是 | 组件列表，**顺序就是组件在工作表里的顺序**，至少一个 |

### 组件

| 键 | 必填 | 意思 |
| --- | --- | --- |
| `type` | 是 | 显示形式，取 `viewer.html` 里 `COMPONENT_TYPES` 的键：`graph` / `scatter` / `histogram` / `spectrum` / `track` / `gauge` / `delta` / `status` / `report` / `chreport` |
| `x` `y` `w` `h` | 否 | 格子位置与大小，缺省用这一类自己的默认尺寸（`x`/`y` 缺省 0） |
| `config` | 否 | 这一类的配置项，能写什么由 `viewer.html` 里这一类的 `defaults()` 决定（例如 `gauge` 的 `subtype`、`graph` 的 `mode`、`histogram` 的 `bins`） |
| `pick` | 否 | 通道从本场次里挑，见下 |

### 挑通道

**为什么不让工作表直接写死通道名**：换一个场次，通道可能叫别的名字或者干脆没有。
`pick` 让工作表说"我要这几类通道"，打开哪个场次就用那个场次的通道去填。

`pick` 是 `{配置键: 规则}`。配置键就是组件 `config` 里的键（`graph` 用 `channels`，
`histogram` 用 `channel` 和 `colour`）。规则可以是**一条**，也可以是**一串**（前面的
挑不到就用后面的，第一个有结果的赢）。

一条规则的键：

| 键 | 意思 |
| --- | --- |
| `patterns` | 用来找通道的关键词（不区分大小写，包含就算命中）。不写就用工作表顶层的 `hints` |
| `limit` | 最多先收几条候选，缺省 1 |
| `index` | 取第几条（从 0 数）。写了 `index` 就是取**一条**，没写到就是取**一整排** |
| `special` | 少数只有界面自己知道的挑法。现在只有一个：`"report"` = 挑快照里真的带了的那几条（`limit` 条） |

找不到就是 `null`（或空数组），组件照常画，只是那一条没数据——**不会**因此把工作表里
别的东西改掉。

例：`{"limit": 5, "index": 4}` = "按 `hints` 找，先收 5 条，取第 5 条"。

## 和工作台的关系

* 按钮上的名字、组件从哪来，都只认这些文件；界面里拖过的布局存在浏览器本地
  （`localStorage`），换了工作表就会覆盖，改回原来的工作表不会带你改过的版本回来。
* 快照（`out/<场次>.html`）把这几份文件一起内嵌进去，所以离线打开照样能切工作表。
* 想把自己拖好的布局存成文件：等「另存为」做好（ticket #33），或手工照上面的格式写一个。
